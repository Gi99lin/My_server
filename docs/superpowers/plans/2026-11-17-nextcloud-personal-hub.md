# Nextcloud Personal Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the owner's Nextcloud into a personal hub (calendar, task lists, notes, project files) that Claude operates natively through a local MCP server and keeps tidy by itself.

**Architecture:** Nextcloud 32 on `gigglin-personal` gets the shipped-store apps Calendar, Tasks and Notes. On the Mac, `nextcloud-mcp-server` runs over stdio through a wrapper that reads an app password from the Keychain, and is registered in Claude Desktop and Claude Code. Upkeep rules live in the global `~/.claude/CLAUDE.md`, and a weekly scheduled task in Claude Desktop runs the review.

**Tech Stack:** Nextcloud 32.0.8 (`occ`), CalDAV/WebDAV, `nextcloud-mcp-server` 0.213.1 via `uvx` (Python ≥ 3.11), macOS Keychain (`security`), Claude Desktop + Claude Code MCP config, macOS/iOS Reminders and Calendar.

**Spec:** [`docs/superpowers/specs/2026-11-17-nextcloud-personal-hub-design.md`](../specs/2026-11-17-nextcloud-personal-hub-design.md)

## Global Constraints

- The hub is personal only: no work (corporate) tasks, notes or files, ever.
- The agent acts as the owner's own Nextcloud account through a dedicated, revocable app password named `claude-mcp (Mac)`.
- Credentials never go into the repo, memory files or MCP config files. The app password lives in the Keychain, service `HomeLab nextcloud-mcp`, account = owner's Nextcloud username.
- The owner creates credentials and CalDAV accounts themselves; the agent never types passwords.
- Tasks have exactly one store: Nextcloud Tasks (CalDAV `VTODO`). Deck is not installed.
- Layout: task lists `Inbox` + one per project; notes in `Notes/<Project>/`; files in `Projects/<Project>/`; finished projects in `Archive/`; hub housekeeping notes in `Notes/Hub/` (`Retro`, `Reviews`).
- Stale task = `LAST-MODIFIED` older than 21 days. Weekly review cadence = 7 days.
- The agent never deletes notes, files, events or tasks without confirmation; it prefers archiving and moving.
- Pin `nextcloud-mcp-server==0.213.1`.
- No custom MCP server. If a required operation is missing, switch to another ready-made server; a thin custom tool needs the owner's OK.
- Nextcloud host: `https://cloud.gigglin.tech`. Server access: `ssh gigglin-personal`, container `nextcloud`, `occ` as `www-data`.

## Review Focus

1. **Claude Desktop starts the MCP without a terminal.** A Keychain read that needs approval or fails must exit non-zero with a clear stderr line within 5 s, not hang. Test in Task 3.
2. **First `uvx` run downloads the package**, which can exceed the client's start timeout. Pre-warm the cache, and check that the second start takes under 10 s. Test in Task 3.
3. **Proxifier on or off.** `cloud.gigglin.tech` must be reachable from the Mac both ways. Test in Task 3.
4. **Edits made in Reminders on the iPhone or Mac must update `LAST-MODIFIED`**, or the stale rule silently stops working. Test in Task 6.
5. **The owner casually asks to file a work item.** The agent must point to the personal-only rule instead of filing it. Test in Task 7.

### Task 3: MCP wrapper and app password

**Files:**
- Create: `nextcloud/mcp/nextcloud-mcp-stdio.sh`. This is the repo copy; install it as `~/.local/bin/nextcloud-mcp` (symlink).
- Create: `nextcloud/mcp/README.md`: what the script does, the Keychain entry, how to revoke the password.

**Interfaces:**
- Produces: the executable `~/.local/bin/nextcloud-mcp`. It speaks MCP over stdio and takes no arguments.
  - Env inputs: `NEXTCLOUD_MCP_USER` (default: the owner's username).
  - Keychain: service `HomeLab nextcloud-mcp`.
  - On failure, it exits 1 with a single line `nextcloud-mcp: <reason>` on stderr.

- [ ] **Step 1: Owner action.** In Nextcloud, go to Settings → Security → Devices & sessions and create the app password `claude-mcp (Mac)`. Store it with `security add-generic-password -U -s "HomeLab nextcloud-mcp" -a <username> -w` (it prompts for the value, so it never lands in shell history). Wait for the owner to confirm.
- [ ] **Step 2: Write a failing check.** Write `nextcloud/mcp/smoke-test.sh`. It pipes an MCP `initialize` request followed by `tools/list` into `~/.local/bin/nextcloud-mcp`, then asserts that the response contains `"serverInfo"` and that `tools/list` has at least one tool with `calendar` in its name. Run it now. Expected: FAIL (the script does not exist yet).
- [ ] **Step 3: Write the wrapper.** `nextcloud-mcp-stdio.sh` uses `set -euo pipefail`. It reads the password with `security find-generic-password -s "HomeLab nextcloud-mcp" -a "$user" -w`, wrapped in `timeout 5` (Review Focus 1). Then it runs `exec uvx nextcloud-mcp-server==0.213.1 run --transport stdio` with `NEXTCLOUD_HOST`, `NEXTCLOUD_USERNAME` and `NEXTCLOUD_PASSWORD` exported only into that process.
  - The wrapper never writes anything to stdout except MCP traffic.
  - Run `uvx nextcloud-mcp-server==0.213.1 run --help` to find any switch that disables unused apps (Deck, Cookbook, Tables, News). Disable them if the switch exists; otherwise note "not available".
- [ ] **Step 4: Run the smoke test.** The first run also pre-warms the `uvx` cache. Expected: PASS. Then time a second run. Expected: under 10 s (Review Focus 2).
- [ ] **Step 5: Run the failure cases.**
  - Run with `NEXTCLOUD_MCP_USER=nobody`. Expected: exit 1 within 5 s and stderr `nextcloud-mcp: no app password in Keychain` (Review Focus 1).
  - Repeat the smoke test with Proxifier turned off. Expected: PASS (Review Focus 3).
- [ ] **Step 6:** Commit the script, smoke test and README: `feat(nextcloud): local stdio MCP wrapper for personal hub`.
